Issue referenced NC61 credit notes for full or partial returns of POS
boletas 39/41. Returns can take place at another store of the same
company in CLP. The original sale determines the accounting mode:

- Standard: a native posted accounting credit note is the fiscal source.
- Session summary: the negative POS order is the fiscal source; native
  session closing accounts for the return without an individual
  accounting credit.

The addon reuses native payments, inventory returns, session closing and
the DTE issuance, evidence, note-reference and A4 report services. Root
locking and native refund quantities prevent adjustments beyond the
original fiscal and physical capacity. The currently supported fiscal
environment is Demo.

Configuration
=============

A DTE manager enables Chilean POS returns in the company settings after
closing all active POS sessions. New sessions freeze the policy. Keep
the existing company accounting-mode selector; each return preserves its
original sale's mode even if the receiving session uses another mode.

Cashiers need Internal User, POS User and DTE User permissions.
Configure manual cash or bank payment methods and the receiving store's
native stock picking type. A current CAF61 and signing profile are
required by the existing DTE services. No additional accounting ACL or
raw fiscal-evidence access is granted to cashiers.

The addon currently requires Chile, CLP, 19% VAT or exempt original
details and Demo evidence. Enabling this option does not change a
company's SII environment.

Usage
=====

1. Open the receiving POS session and select Return.
2. Find an accepted original POS boleta 39/41 from any store of this
   company.
3. Select quantities and enter a reference reason of 1 to 90 Latin-1
   characters.
4. Review the online preview and choose a manual refund payment method.
5. Validate online. Hand over the refund only after server confirmation.
   The cashbox opens after the confirmed NC61, and the operational
   receipt identifies the credit note and its original boleta.

If the response is uncertain, reconnect and validate the same order and
UUID. Do not create another return or pay the customer again. A
confirmed server validation error leaves an editable draft; an uncertain
response preserves the order identity until it can be recovered.

A complete untouched original uses cancellation reference code 1.
Partial returns and remaining quantities after earlier adjustments use
reference code 3. The server recomputes amounts with Odoo's tax engine
and validates both the financial balance and previously returned
quantities. Native POS prices stay unchanged; NC61 serializes the
original net fiscal unit price.

For older sales without line identity evidence, a DTE manager uses
Prepare Legacy Line Mapping on the original order. Only an exact unique
correspondence is accepted; ambiguous duplicate details block the return
without guessing or rewriting the original snapshot or XML.

Lotted products require one original lot per POS detail. Serial numbers
must come from the original native stock movement and cannot be returned
twice. The return uses the receiving store's picking type. Fiscal order
lines, payments and lot identities become immutable after issuance.

A DTE manager can create and generate the existing A4 print sample from
the NC61 in either accounting mode. Its source is the signed XML,
including PDF417 and the original reference. The POS operational receipt
does not replace this report. Queued means pending fiscal confirmation.
Rejected or uncertain credit notes preserve payment, stock and evidence
and block session closing for review.

Known issues / Roadmap
======================

This first delivery excludes mixed exchanges, multiple original sales
per return, offline completion, automatic terminal/online/QR refunds,
cash rounding, combos, rewards, tips, advances and zero-value fiscal
details. Partial notes support at most 60 fiscal details.
Unrepresentable CLP rounding is blocked before completing the refund; no
fictitious adjustment product is introduced.

Multi-lot allocation within one original detail, thermal fiscal NC61
printing, recovery of definitively rejected notes and operation beyond
the currently supported Demo environment require separate increments. No
official SII certification or production acceptance is implied by local
tests.
