Requests CAF folio authorizations from the SII with an auditable,
idempotent workflow, and keeps folio stock replenished through
per-company rules.

- The SII issues CAFs through its certificate-authenticated web
  assistant (``cvc_cgi/dte/of_solicita_folios``). This addon owns the
  client of that assistant: AUT2000 login with the company certificate
  over in-memory mTLS (PycURL), the request form, the folio allocation
  and the CAF download, and the re-download of already authorized ranges
  (``rf_reobtencion*``). The host follows the explicit environment of
  each request: Certification on maullin, Production on palena, with the
  same paths. ``l10n_cl_dte_certification`` reuses the same client fixed
  to Certification.
- Requests move through ``pending``, ``approved``, ``running``,
  ``success``, ``partial``, ``failed``, ``uncertain``, ``reconciled``
  and ``cancelled``. Each run is a numbered attempt, committed as
  running before any SII call. Right before the POST that makes the SII
  allocate folios, the attempt is durably marked as dispatched together
  with the folio range the assistant reserved.
- The exact SII download response (the CAF) is stored as an attachment
  with its SHA-256 digest. The CAF is registered and validated through
  ``l10n_cl_dte_caf`` before any folio can be reserved from it.
- Error codes distinguish login/authentication, certificate, SII
  rejection, unused-folio blocking, quantity limit, CAF validation and
  post-dispatch uncertainty. Stored messages are fixed texts;
  certificates, keys and session cookies are never logged or stored.
- A failure after the allocation POST makes the request ``uncertain``;
  it is never sent again. **Recover CAF from SII** downloads the CAF of
  the recorded range (it never allocates folios) and reconciles the
  request; an operator may also reconcile it with a CAF obtained
  independently. Transient failures before allocation can be retried up
  to three attempts.
- Folio availability comes from the validated CAFs and the reservation
  ledger of ``l10n_cl_dte_caf``; this addon keeps no ledger of its own.
- Replenishment rules per company, DTE type and environment queue a
  request when availability falls to the threshold. Queued requests wait
  for operator approval unless the rule explicitly opts in to automatic
  execution, which only the scheduled job performs. Acquisition never
  runs inside invoice creation, numbering or signing.

Port of the CAF acquisition of the SMWLAB module
``l10n_cl_edi_caf_auto``, on top of the SII assistant client first
written for ``l10n_cl_dte_certification``.

Usage
=====

Configure a signing profile with a valid certificate and its private key
for the SII environment (``l10n_cl_dte_signing``) and the company RUT.
The server needs PycURL built against OpenSSL and libcurl 7.71 or later.

To request folios manually, a DTE manager opens *DTE > Operations > SII
CAF Requests*, creates a request with the environment, DTE type and
quantity, approves it and presses **Request CAF from SII**. On success
the new CAF is validated and linked to the request; the SII response can
be downloaded from the *Evidence* tab.

- A ``failed`` request that never reached the allocation step and failed
  for a transient reason (connection, session) shows **Retry**.
- An ``uncertain`` request must not be sent again. Press **Recover CAF
  from SII** to download the CAF of the reserved range and reconcile it.
  If the SII does not list the range, the request stays uncertain with
  the recovery code; import the CAF manually in *CAF Authorizations*,
  select it in *CAF for Reconciliation* and press **Reconcile**.

To replenish automatically, create a rule in *DTE > Configuration > CAF
Replenishment Rules* with the threshold and quantity. The hourly job
queues a pending request when availability is at or below the threshold.
Choose *Automatic Execution by the Scheduled Job* and an *Execute As*
DTE manager to let the second hourly job run those requests without
approval.

Production uses the same assistant flow that Certification already uses,
on the palena host. Run one manual Production request and check its CAF
before enabling automatic execution in Production.
