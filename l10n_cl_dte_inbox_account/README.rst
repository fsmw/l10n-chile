Incoming DTE vendor bills
=========================

Prepare or link a native draft vendor bill from a reviewed Chilean
incoming DTE 33/34. The bridge keeps the received XML in the immutable
inbox and records the supplier, source digest, approved accounting
choices and bill in a separate immutable binding.

The user reviews and confirms each operation. The bridge does not post
bills, import payments, create suppliers/products or contact the SII.

.. IMPORTANT::
   This is an alpha version, the data model and design can change at any time without warning.
   Only for development or testing purpose, do not use in production.
   `More details on development status <https://odoo-community.org/page/development-status>`_

Configuration
=============

Configuration
=============

1. Grant **Incoming DTE Vendor Bill Configuration** to the accounting
   supervisor and **Incoming DTE Vendor Bills** to operators. The
   operator role includes native Billing and DTE read access. It does
   not grant the DTE manager role.
2. In Accounting settings, select a Chilean CLP company with one-peso
   rounding, enable incoming vendor bills and choose an active LATAM
   purchase journal.
3. Choose excluded purchase VAT 19% (SII code 14) and an explicitly
   designated exempt purchase tax at 0% (SII code 0). The bridge does
   not create taxes.
4. Maintain existing suppliers with a valid Chilean RUT and native
   taxpayer type. Missing, archived or ambiguous commercial suppliers
   block the preview.
5. Configure exact supplier item-code, description or supplier-default
   mappings to existing accounts, taxes and optional products/units.
   Code takes precedence, then exact whitespace-normalized description,
   then supplier default. Conflicting item codes block the operation.
   Archived mappings are ignored; their keys remain reserved so they can
   be edited or restored without duplicating configuration.

Products are optional. Every fiscal line requires an active company
account and a compatible purchase tax. Source units need an explicit
matching unit mapping or an explicit unit choice in the preview;
quantities are never converted.

General company settings retain native Odoo Settings administration
permissions. The bridge configuration role does not grant those global
administration rights. An Odoo administrator with the bridge
configuration role saves the company journal, VAT, exemption and enabled
flag together. Mapping managers can maintain mappings without receiving
general Settings administration rights.

Known issues / Roadmap
======================

Supported scope and limitations
===============================

This delivery supports ordinary net-price CLP DTE 33/34, excluded
purchase VAT 19% and exempt lines, explicit quantities/prices,
percentage line discounts, and an optional source due date. Unsupported
economic features are diagnosed without changing the inbox evidence or
its validation state.

Global discounts/charges, gross pricing, extra taxes/withholdings,
commissions, foreign currencies, credit/debit notes and non-billable
components are outside this delivery. Missing quantities/prices are not
inferred. XML payment metadata is informational and never creates
payments or reduces the invoice balance.

The addon retains Alpha maturity while its inbox dependency remains
Alpha. Functional local tests do not constitute SII certification.
Review actual supplier XML diversity before extending the conservative
supported subset.

Supplier-root mergers with existing bindings require a future assisted
migration. Before uninstalling the addon, export/back up its provenance:
Odoo removes addon fields/tables during uninstall, even when the
original inbox and bills survive.
