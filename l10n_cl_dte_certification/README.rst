Preserves the original SII certification set TXT per company, including
its exact bytes, filename, size and SHA-256 digest. Imported source
records are immutable and can only be created through the import wizard.

Usage
=====

Import an original SII certification set from the DTE Operations menu,
under Certification Sets and Import Original SET. The source is stored
as evidence. DTE managers can analyze numbered sections, ordered cases,
document types, and source lines, then create immutable case snapshots
that preserve the exact instructions, source digest, and line ranges.
Unrecognized document types stay visible as unsupported cases. This does
not create accounting documents or consume folios. Re-importing the same
bytes for the same company is rejected. No source data is included in
this addon.

DTE managers can interpret case snapshots after reviewing them. This
versioned pass extracts only explicit detail columns, note references
and correction markers. It keeps source-line provenance for extracted
values and reports unrecognized or incomplete instructions for review.
It does not create accounting documents, resolve business partners or
products, reserve folios, or send information to the SII.

The case coverage summary separates interpreted cases from those needing
review, unsupported document types, and cases not yet interpreted. The
coverage check reports these counts and stays in warning state until
every case has been reviewed successfully.

Recognized detail rows are materialized as ordered, immutable case-line
snapshots. Each row retains its explicit values, source line, source
digest, and interpreter version for later operator mapping.

Item quantities, prices, and discounts are checked with decimal
arithmetic. Out-of-range values remain visible with their source
evidence and put the case in review; they are never silently corrected.

Global discounts, note references and reasons, note operations, text
corrections, and interpretation diagnostics are also shown as
structured, read-only case facts with their original line references.

Recognized note reasons map to a separate SII reference code
(``CodRef``); the source reason remains intact for ``RazonRef``. Unknown
reasons and note/document type mismatches require review. When a newer
interpreter is introduced, a DTE manager must explicitly reinterpret
outdated cases; the previous and new interpretations are retained in an
immutable history.

Interpreted note references are linked to one case in the same attention
section. Missing targets, targets that occur later in the SET, and
targets with an incompatible document type stay in review and cannot be
used for generation.

After every case has been interpreted successfully, DTE managers can
create an execution from the certification set. The selection must
include every case referenced by a selected note and the complete chain
of earlier references. The execution stores immutable, hashed snapshots
of the selected instructions, interpretation, detail rows, references,
and source evidence. Creating an execution does not create accounting
documents, reserve folios, or send data to the SII.

DTE managers can generate drafts and prepare signed DTEs for the
execution. Once every case is prepared, Export Certification Envelope
validates the frozen case links and signed XML evidence, composes and
schema-validates a signed EnvioDTE, and saves its exact bytes and
SHA-256 digest for repeatable download. This is an offline export only;
it does not authenticate to, upload to, or query the SII.

After reviewing the stored XML and digest, a DTE manager can explicitly
submit that envelope through the configured Certification gateway. The
execution links to one durable gateway record, which retains the
request, TrackID, status attempts, and response evidence. If transport
outcome is uncertain, the workflow preserves that state and does not
retry the upload automatically; operators must inspect the transmission
record and recover through the SII portal before taking further action.

After importing the SII result XML on the transmission record, a DTE
manager can reconcile the imported EPR against the frozen execution
cases. The snapshot matches issuer, receiver, document type, folio, and
the exact submitted-envelope digest; it displays the reported result and
detail per case while preserving the gateway's operator-attestation
label. It does not verify the supplied result signature, change the
DTE/accounting state, or approve a portal certification stage.
